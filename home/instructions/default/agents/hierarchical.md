# Delegated work

Use delegation only when the active client exposes collaboration tools and the
work can proceed independently. Keep the critical path and integration decision
with one coordinator. Do not spawn workers merely to increase activity.

Give each child the objective, relevant evidence, allowed paths, non-goals,
permission ceiling, expected output and stop condition. Assign one writer per
shared file. Use read-only exploration or review when edit ownership would overlap.

Select the narrowest fitting role. Wait for required results, check their evidence,
resolve disagreements against the source, and close completed child threads. Do
not broaden the user's task through delegation or claim a child's unverified
summary as a successful test or deployed change.
